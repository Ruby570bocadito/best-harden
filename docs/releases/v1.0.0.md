Adarve 1.0 cumple la frase con la que se acotó el proyecto: llevar el binario en un USB, auditar Windows 11, Windows Server 2022 y Ubuntu 24.04, endurecerlos con rollback y entregar un informe defendible, sin falsos positivos conocidos y con una release firmada.

Es también la primera versión con licencia: [Apache 2.0](https://github.com/Ruby570bocadito/adarve/blob/main/LICENSE).

## Instalar

```bash
# Linux, como root
curl -fsSL https://raw.githubusercontent.com/Ruby570bocadito/adarve/main/scripts/install.sh | sudo bash
```

```powershell
# Windows 10/11 o Windows Server 2016-2025, en PowerShell como administrador
irm https://raw.githubusercontent.com/Ruby570bocadito/adarve/main/scripts/install.ps1 | iex
```

Opciones, espejos internos y despliegue con GPO, Intune o Ansible: [instalación](https://github.com/Ruby570bocadito/adarve/blob/main/docs/09-instalacion.md) y [guía de operación](https://github.com/Ruby570bocadito/adarve/blob/main/docs/17-guia-de-operacion.md).

## Si vienes de Bastion

Bastion pasa a llamarse Adarve. **Vuelve a ejecutar el instalador**: traslada la configuración, los informes, las excepciones, las instantáneas y la ronda diaria (a la misma hora), y retira el binario y la tarea antiguos. `adarve rollback` sigue deshaciendo los cambios que aplicó Bastion.

`bastion update` no encuentra esta versión, porque los archivos se llaman ahora `adarve_<sistema>_<arquitectura>`: usa el instalador.

## Qué hace

- **La ronda (`adarve scan`):** 161 controles para Windows 10/11, Windows Server 2016-2025 (miembro y controlador de dominio) y Linux, con perfiles por rol en niveles 1 y 2. Solo lectura, con evidencia de cada control, puntuación ponderada, MITRE ATT&CK, excepciones con caducidad e informe HTML autocontenido o JSON estable.
- **Reparar (`adarve harden`):** 121 controles se reparan solos, por olas según el riesgo de rotura. Antes de tocar nada guarda una instantánea, verifica cada cambio y deshace el que no funciona; `adarve rollback` lo deja como estaba. Los cambios de SSH y RDP llevan un dead-man switch que los deshace si pierdes el acceso, también tras un reinicio.
- **Las puertas (`adarve surface`):** qué escucha en la red, qué programa y de dónde viene, qué deja pasar el firewall (Windows, nftables o iptables), recursos compartidos y quién es administrador.
- **La ronda diaria (`adarve schedule`):** con el Programador de tareas, systemd o cron, y avisos en el Visor de eventos, syslog o un webhook.
- **La consola (`adarve ui`):** la muralla por tramos, la simulación de las olas, las puertas, las rondas y las excepciones, solo en `127.0.0.1` y con token.

## Novedades desde Bastion 0.4.3

- Nuevo nombre e identidad: la muralla, sus tramos y sus brechas en la consola y en los informes, con un diseño nuevo de noche y de día.
- Releases firmadas (ECDSA P-256) y verificadas por `adarve update` y los instaladores, con atestación de procedencia SLSA y SBOM de cada archivo.
- Estado `manual` para lo que solo puede juzgar una persona (quién es administrador, quién puede usar sudo, qué se comparte): Adarve reúne la evidencia y no lo cuenta en la puntuación.
- sudo-rs (Ubuntu 25.10 y posteriores) y Ubuntu 26.04.
- El dead-man switch es una tarea del sistema y sobrevive a un reinicio.
- SSH en Ubuntu con activación por socket: se valida sin efectos secundarios y el rollback restaura `sshd`.
- Formatos congelados (`adarve.report/v1`, `adarve.surface/v1` y los demás) con una política de compatibilidad escrita y comprobada por tests.
- Guía de operación: qué hacer si un rollback falla y cómo desplegar por GPO, Intune o Ansible, con ejemplos que el CI prueba en máquinas reales.
- Laboratorio: el estado de cada control en Ubuntu 24.04 y Windows Server 2022 y 2025 recién creados se compara con su resultado esperado, revisado a mano, en cada cambio y cada lunes. En su primera ronda destapó un falso positivo que fallaba en cualquier Windows (WIN-DEF-013, exclusiones de Defender) y dos errores de probe en Windows Server 2025, corregidos en esta versión.

## Verificar la descarga

```bash
curl -fsSLO https://raw.githubusercontent.com/Ruby570bocadito/adarve/main/internal/selfupdate/release-signing.pub
openssl dgst -sha256 -verify release-signing.pub -signature checksums.txt.sig checksums.txt
sha256sum --ignore-missing -c checksums.txt
gh attestation verify adarve_linux_amd64.tar.gz --repo Ruby570bocadito/adarve
```

Los instaladores y `adarve update` hacen esta comprobación solos y rechazan una release sin firma o con una firma que no es la de Adarve.

## Límites conocidos

- GitHub no tiene runners de Windows 11: el laboratorio prueba sus reglas en Windows Server 2025, que comparte compilación con Windows 11 24H2. Quedan fuera las cuatro reglas exclusivas de cliente y las de controlador de dominio, que esperan a un laboratorio propio.
- `adarve surface fix` solo existe en Windows; en Linux, `surface` informa y propone, pero no cambia el firewall.
- En máquinas reales, el CI aplica la ola 1 de `harden` y los cambios de SSH con su dead-man switch; las olas 2 y 3 completas se prueban en el motor y en simulación.
